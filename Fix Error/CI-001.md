# CI-001 — Runtime CLI regression contract drift

Status: IN_PROGRESS
Severity: MEDIUM

## Reproduction

The regression test imported `live.live_runtime_cli.build_parser()` and asserted the
current operational CLI contract. The implementation had the required operational
flags, but the test was asserting `--mode LIVE` while the project safety defaults
and this test suite are intended to exercise the hardened CLI without requiring a
live broker session.

A second issue was found during the same review: `--interval` was only validated
inside `main()`, so `build_parser().parse_args(["--interval", "0"])` accepted an
invalid value. That weakens the parser-level contract and makes configuration
errors discoverable later than necessary.

## Observed behavior

- Regression test and implementation had drifted around the CLI contract.
- Parser accepted non-positive numeric runtime limits.

## Expected behavior

- Regression tests should exercise the current CLI contract without requiring a
  broker or real execution.
- Invalid positive-only runtime limits should fail during argument parsing.

## Root cause

The CLI contract evolved while the regression test retained assumptions from an
older version. Numeric validation was also split between parser construction and
`main()`, leaving parser consumers with weaker validation.

## Fix

- Updated `tests/test_live_runtime_cli.py` to match the current defaults and
  operational flags.
- Added regression coverage for invalid non-positive intervals.
- Added a shared finite-positive float parser to `live/live_runtime_cli.py` and
  applied it to risk, interval, tick age, spread, and daily drawdown arguments.
- Kept execution mode defaulted to `DEMO` in the regression contract.

## Regression test

`tests/test_live_runtime_cli.py`

Required checks:

- DEMO is the default mode.
- Current defaults remain stable.
- Operational limits are parsed as finite positive floats.
- Non-positive intervals are rejected by argparse.

## Verification evidence

- Code and regression test updates committed to `main`.
- GitHub Actions polyglot-security job was previously cancelled; it was explicitly
  re-run after the changes.
- This incident must not be marked `FIXED` until the relevant CI run completes
  successfully.
