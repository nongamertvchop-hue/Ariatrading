# WEB-001 — Webaria controls and MT5 strategy path were not fully connected

## Status

**OPEN — verification pending on deployed site**

## Symptom

The Webaria terminal could show market candles, but the live-market bridge explicitly replaced strategy state with `WAIT`. This meant the visible strategy panel could not reflect the actual two-setup engine using the same MT5 candles shown on the chart. Some controls also lacked a single explicit interaction contract.

## Root causes found

1. `Webaria/live-market.js` used `/api/market` for MT5 candles but did not pass those candles into the strategy engine. It instead forced a `WAIT` state.
2. The older `/api/signal` compatibility endpoint can use Twelve Data or a deterministic fallback, so it was not a valid source of truth for an MT5-backed live chart.
3. UI handlers were distributed across scripts without one clear interaction contract.

## Fix applied

### MT5 → strategy connection

Added `Webaria/functions/api/strategy.js`. It accepts the already validated completed candles from `/api/market` and calls the existing `evaluatePriceAction()` implementation. This keeps the strategy decision on the same market data that the user sees on the chart.

`Webaria/live-market.js` now:

- obtains market data from `/api/market`;
- keeps the forming candle for display only;
- sends completed MT5 candles to `/api/strategy`;
- renders the returned LONG/SHORT/WAIT decision, structure, breakout state, score and reason;
- records the observed result in the browser signal journal;
- fails closed when either market or strategy data is unavailable.

The adapter always reports `source: "mt5"` and `execution: "NONE"`; it does not submit broker orders.

### UI control contract

`Webaria/ui-controls.js` remains responsible for the primary terminal controls and must report unavailable controllers instead of silently failing.

## Regression coverage

Added `tests/webaria_strategy_api.test.mjs` covering:

- valid MT5 candle payloads;
- insufficient candle history;
- malformed OHLC;
- execution remaining `NONE`.

## Verification required

A fix is not considered closed until these are verified on the deployed site:

1. Browser console has no blocking JavaScript errors on initial load.
2. `/api/market` returns MT5-sourced data when the bridge is connected.
3. `/api/strategy` evaluates the same completed MT5 candles shown by the chart.
4. The strategy panel changes from the hard-coded live `WAIT` state when the engine returns a directional signal.
5. Timeframe and symbol controls refresh the MT5 chart and strategy together.
6. Paper orders remain simulation-only.
7. No browser control bypasses the Python/MT5 live execution safety boundary.

## Closure rule

Do not mark this incident resolved from source inspection alone. Deployment and browser verification are required.
