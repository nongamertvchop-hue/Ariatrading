# WEB-001 — Webaria controls looked functional but some interactions were not backed by a real state transition

## Status

**OPEN — verification pending on deployed site**

## Symptom

A user can see a TradingView-like terminal and press controls, but a control may appear to do nothing, or UI state may not clearly prove that the requested action happened.

## Reproduction checklist

- Open Webaria terminal.
- Press `Fit`, `Crosshair`, `Refresh`, `Reset view`.
- Change timeframe from the top selector and bottom timeframe bar.
- Select a symbol from Market Watch.
- Open/close the Panel on mobile width.
- Switch Watchlist / Details.
- Use chart tools and verify a state change is visible.
- Press LONG/SHORT only in the explicitly labelled paper-trading simulation.

## Root cause found

The UI had individual handlers spread across chart/runtime scripts without one explicit interaction contract. That made it possible for a visible control to exist without a strong guarantee that it mutated chart state, refreshed the data controller, or reported why it could not act.

## Fix applied

`Webaria/ui-controls.js` now owns the contract for the primary terminal controls. It:

- routes refresh to the market/data controller;
- resets and fits the chart through the actual chart state;
- toggles crosshair state and ARIA state;
- changes timeframe through the real selector event;
- switches the panel state;
- activates chart tools;
- switches Watchlist/Details with real rendering;
- reports unavailable controllers instead of silently failing.

The control layer never places broker orders.

## Related architecture

- `Webaria/trading.js` — chart state and rendering
- `Webaria/live-market.js` — MT5 market-data display path
- `Webaria/paper-terminal.js` — browser-only paper trading
- `Webaria/ui-controls.js` — control interaction contract
- `worker/` + `Webaria/functions/api/` — API/data path
- `live/` — MT5 execution safety boundary

## Verification required

A fix is not considered closed until these are verified on the deployed site:

1. Browser console has no blocking JavaScript errors on initial load.
2. `/api/market` returns MT5-sourced data when the bridge is connected.
3. `/api/signal` returns a valid response for supported symbol/timeframe combinations.
4. Each control visibly changes state or returns an explicit error.
5. Paper orders remain simulation-only.
6. No browser control can bypass the Python/MT5 live execution safety gate.

## Closure rule

Do not mark this incident resolved from source inspection alone. Deployment and browser verification are required.
